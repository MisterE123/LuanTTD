# An owned stock rail depot roster

`rail_depot_fleet.lua` connects the isolated stock roster to actual owned Trackworks depots and company cash. It is a persisted, explicit one-locomotive consist builder. A successful purchase stores the ordered stock IDs, per-part purchase value and build date, locomotive initial reliability and life, and unique owned unit identity. Nothing is in movement until the host explicitly starts it.

## Mount contract

- Load with `dofile(path)(Sim, Trackworks, RailRoster)` and call `F.initialize(S, cfg)` **once** for a stock fleet world. The game needs an explicit original `starting_year`, `generation_seed` and its stock startup engine RNG draw `startup_random`; it must not reseed a restored fleet. World climate defaults to Temperate. Calendar advances in Gregorian days from the selected year's January 1, using `S.day - calendar_origin_day` (default origin 0), not the former 30-day HUD calendar. No imported arbitrary-date or wallclock game is implied.
- `F.catalog(S)` lists the available subset, raw stock properties, actual stock designs' introduction dates, seeded reliability phases, and whether the explicit preview is enabled. The adapter implements general public introduction and retirement. It does not issue exclusive preview offers or assign a prototype to individual businesses. At a default seeded 1950 Temperate start the Kirby Paul Tank, Chaney ‘Jubilee,’ Ginzu ‘A4,’ Passenger Carriage and Coal Truck meet ordinary source purchase eligibility. The Floss ‘47’ is unavailable at the 1950 start and eligible at the 1966 Temperate start; player-facing quotes for each newly modeled class also require its exact native asset. Older fleet saves derive added roster rows from their existing persisted seeds without changing previously purchased stock. The MJS 250 is an arctic/tropical locomotive with later availability; `roster_preview=true` is a deliberate nonstock override for experimentation only.
- `F.quote(S, owner, depot, {0,27,...}, hooks)` returns a detached proposal for a currently owned depot and company. There must be exactly one lead locomotive and zero or more supported wagons. It enforces train length limits, pool and company train limits, railtype compatibility and stock availability. Optional runtime hooks supply actual price settings, occupied vehicle slots outside this fleet, other company rail unit numbers, and company railtype flags. Defaults are 500 trains per company, stock 7 tiles per train, stock vehicle-pool ceiling; without a host counter only legacy `S.fleet` plus this rail fleet use the pool tally.
- `F.commit(S, owner, quote, hooks)` rechecks the depot, selected rows, latest stock availability, price, owner and funds. It allocates the first unused company train number and debits company cash and expenses exactly once. The monotonically increasing saved sequence invalidates a used quote after reload. Cash and the receipt inhabit the same save snapshot. The host should persist that complete state together after each accepted command. Failed/repeated buys don't spend, allocate, or create a company.
- `F.get(S, owner, id)` and `F.list(S, owner[, depot])` return copies of owned records. The adapter uses `S.stock_rail_fleet`; there are no functions or metatables in the saved data. Call `F.occupies_depot(S, depot)` before removing a depot containing a staged consist.
- `F.prepare_dispatch(S, owner, id, hooks)` returns a detached depot, stock IDs, ordered parts and exact roster stats without spending or changing status; it rechecks the surviving depot. After a successful runtime dispatch, bind with `F.bind_dispatch(S, owner, id, run_id)`, where the host uses a stable numeric run reference unique among fleet records. This does not create a dispatch, charge again, move the train, bind cargo, or return an active train to depot. Host run/controller validation and rollback belong with the actual runtime mount.

Stock limits, build predicates and design reliability/eligibility are sourced from 14.1 `engine.cpp`, `random_func.cpp`, `vehicle_cmd.cpp`, `vehicle.cpp`, `train_cmd.cpp`, and the stock table and setting defaults. The aggregate purchase is a local interface over normal buy and coupling checks, not the original depot drag, free-wagon autoassembly or stock engine group commands. No live availability dialog, servicing/failure, vehicle cargo transfer or resale is implemented here.

```sh
lua5.1 tests/rail_depot_fleet.lua
PYTHONDONTWRITEBYTECODE=1 python3 tests/rail_depot_fleet_upstream.py /path/to/OpenTTD-14.1 [lua5.1]
```

The first test actually builds owned Trackworks depots; checks 1950 sales, float-free atomic spending, rejected and replayed commands, stock limits, age transitions, and a serialized reload. The C++ differential compiles the pinned startup seed/phase and reliability routines and compares 192,896 stock calendar/seed/climate design snapshots.
